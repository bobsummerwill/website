Omarchy on the second drive, then stress-test the RX 6900 XT

Install Omarchy (Arch + Hyprland) without touching your son's main drive, then prove the card is healthy before listing it. Tick steps off as you go; your ticks stay in this browser.

RX 6900 XT OC · 16 GB 3 × 8-pin ~1.5–2 h total Listing target ~C$600
PrepA · InstallB · TestResultsAfterwards 0 / 0 done

Before you startPrep

  • Back up anything on the second drive. The Omarchy installer wipes the whole drive you pick.
  • Know which drive is your son's. Note its make, model and size (Windows: Disk Management).
  • A USB stick of 8 GB or more. It will be erased.
  • Power: PSU of 750 W or more with three separate 8-pin PCIe cables. No daisy-chained cable feeding two plugs.
  • An Ethernet cable to the router, and a disk-encryption passphrase you'll remember (you type it every boot).
Safest method: physically unplug your son's main drive (SATA data cable, or remove the M.2) while installing. The installer then can't see it and the bootloader can't land on it. Plug it back in afterwards.

Part AInstall Omarchy on the second drive

A1

Download the ISO from omarchy.org and write it with balenaEtcher, or from a Linux terminal:

lsblk                       # find the USB stick, e.g. /dev/sdX (check the size!)
sudo dd if=omarchy.iso of=/dev/sdX bs=4M status=progress oflag=sync

Double-check /dev/sdX is the USB stick. dd overwrites whatever you point it at.

A2

  • Shut down, switch the PSU off at the back, unplug it, press the power button once to drain.
  • Remove the RX 6750 XT. Fit the RX 6900 XT in the top x16 slot and connect all three 8-pin plugs, each on its own cable.
  • Plug the monitor into the 6900 XT, not the motherboard output.
  • Photograph the card's BIOS switch position. Start in the default/performance position.
  • While the case is open, unplug your son's drive.
A3

  • Enter the BIOS (usually Del or F2). Disable Secure Boot; on some boards set OS Type to "Other OS".
  • Make sure it's in UEFI mode, not Legacy/CSM-only. Optional: enable Resizable BAR / Above 4G Decoding.
  • Save, then press the one-time boot menu key: F8 ASUS, F11 MSI/ASRock, F12 Gigabyte/Dell/Lenovo. Pick the UEFI entry for the USB stick.
A4

If you can get a shell, confirm only the second drive and the USB stick appear:

lsblk -o NAME,SIZE,MODEL,SERIAL,TYPE,MOUNTPOINTS
A5

  • Fill in keyboard, username, password, name, email, hostname and timezone. Ethernet usually just works.
  • Disk selection: pick the second drive by size and model. Read it twice. It is erased and fully used.
  • Keep the default full-disk encryption and set the passphrase.
  • Wait 10–30 min (slower on a spinning HDD), remove the USB when told, reboot.
  • First boot: passphrase, then log in. Super+Enter opens a terminal, Super+Space the launcher.
A6

omarchy-update          # full system + Omarchy update; reboot if it asks
  • Shut down, plug your son's drive back in, and in the BIOS put his drive (Windows Boot Manager) first.
  • Start Omarchy from the one-time boot menu (F8/F11/F12) when you need it.
  • Optional: sudo limine-scan in Omarchy adds Windows to Omarchy's boot menu. Not needed for this test.

Part BStress-test the RX 6900 XT

All commands run in an Omarchy terminal. Open several and let Hyprland tile them.

B1

sudo pacman -Syu
yay -S --needed vulkan-radeon vulkan-tools lm_sensors pciutils git cmake \
       base-devel shaderc vulkan-headers glmark2 vkmark amdgpu_top
mkdir -p ~/gputest && cd ~/gputest
B2

lspci -nnk | grep -A3 -i vga        # expect Navi 21 ... 6900 XT, driver amdgpu
GPU=$(lspci | grep -iE 'vga.*(amd|ati)' | awk '{print $1}')
sudo lspci -vv -s $GPU | grep -i lnksta
cat /sys/class/drm/card*/device/mem_info_vram_total   # expect ~17163091968 (16 GB)
vulkaninfo --summary | grep -i devicename             # expect AMD Radeon RX 6900 XT (RADV NAVI21)

Pass: 16 GB VRAM, amdgpu driver, Vulkan sees the card. Screenshot this for the listing.

B3

Terminal 1, kernel errors. Anything printed here during the tests is a red flag:

sudo journalctl -k -f | grep -iE "amdgpu|ring|timeout|reset|fault"

Terminal 2, temperatures, clocks, power and fan:

amdgpu_top        # or:  watch -n1 sensors
Edge< 85 °C
Junction< 100 °C
Memory< 95 °C
Board power255–300 W

Junction (hotspot) more than about 25–30 °C above edge points to dried paste. 100–110 °C junction means it is throttling.

B4

cd ~/gputest
URL=$(curl -s https://api.github.com/repos/GpuZelenograd/memtest_vulkan/releases/latest \
      | grep browser_download_url | grep -i linux | grep -iv aarch64 | head -1 | cut -d'"' -f4)
echo $URL && curl -L -o memtest.tar.xz "$URL"
mkdir -p memtest && tar -xf memtest.tar.xz -C memtest
MT=$(find memtest -type f -name 'memtest_vulkan*' | head -1)
chmod +x "$MT" && "$MT"

Pick the RX 6900 XT if asked, run 20–30 minutes, then Ctrl+C. Pass: zero errors. Any error line means faulty or unstable VRAM.

B5

while true; do vkmark || glmark2; done

Pass: no crashes, black screens, artefacts or kernel messages; temperatures settle inside the limits above.

B6

The test an AI buyer cares about. Builds llama.cpp, downloads a ~5 GB model, and checks the card gives bit-identical output three times. Unstable cards drift.

cd ~/gputest
git clone --depth 1 https://github.com/ggml-org/llama.cpp
cmake -S llama.cpp -B llama.cpp/build -DGGML_VULKAN=ON -DCMAKE_BUILD_TYPE=Release
cmake --build llama.cpp/build -j$(nproc)
curl -L -o qwen3-8b-q4km.gguf \
  https://huggingface.co/Qwen/Qwen3-8B-GGUF/resolve/main/Qwen3-8B-Q4_K_M.gguf

BIN=llama.cpp/build/bin
for i in 1 2 3; do
  $BIN/llama-simple -m qwen3-8b-q4km.gguf -ngl 99 -n 300 \
    "Explain how a graphics card works, step by step." > run$i.txt 2>/dev/null
done
diff run1.txt run2.txt && diff run1.txt run3.txt && echo "IDENTICAL - PASS"

Then a sustained compute load for 10–15 minutes:

while true; do $BIN/llama-bench -m qwen3-8b-q4km.gguf -ngl 99 -p 512 -n 128; done

Pass: "IDENTICAL - PASS", steady pp512 / tg128 numbers run after run, no kernel messages. Screenshot the numbers.

B7

  • Crash, black screen, "ring timeout" or "GPU reset": flip the BIOS switch, reboot, repeat B4–B6.
  • Hotspot over 105–110 °C or a big edge-to-hotspot gap: works but needs new paste (maybe pads).
  • memtest_vulkan errors: faulty VRAM. Sell for parts and say so.
  • Only one BIOS position stable: sell as working, noting the unstable BIOS.
  • Reseat the 8-pin cables and confirm they're on separate PSU leads before blaming the card.

Wrap upAfterwards

Z1
